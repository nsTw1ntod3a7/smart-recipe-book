# Smart Recipe Book — консольный MVP (C# / .NET 8)

Консольная реализация всех 4 модулей из карточки команды.

## Структура проекта

```
SmartRecipeBook/
├── Models/
│   ├── Ingredient.cs        # продукт: название, количество, единица измерения
│   ├── Recipe.cs             # рецепт: название, время, ингредиенты, шаги
│   └── RecipeStep.cs         # один шаг инструкции
├── Pantry/
│   └── PantryManager.cs      # Модуль 1: склад — добавление/списание/просмотр
├── Recipes/
│   └── RecipeCatalog.cs      # Модуль 2: база рецептов — добавление/просмотр
├── Matcher/
│   └── RecipeMatcherService.cs  # Модуль 3: сравнение рецептов со складом
├── Shopping/
│   └── ShoppingList.cs       # Модуль 4а: автогенерация списка покупок
├── Storage/
│   └── RecipeStorage.cs      # Модуль 4б: сохранение/загрузка в JSON-файл
├── Program.cs                 # консольное меню, связывающее все модули
└── SmartRecipeBook.csproj
```

## Как запустить

Нужен установленный [.NET 8 SDK](https://dotnet.microsoft.com/download).

```bash
cd SmartRecipeBook
dotnet run
```

При первом запуске данные пустые. Данные сохраняются в файл `data.json`
рядом с исполняемым файлом (пункт меню "10" или автоматически при выходе
через "0").

## Что реализовано (соответствие модулям из карточки команды)

- **Модуль 1. Виртуальный склад** — `PantryManager`: добавление, списание,
  изменение остатка, просмотр списка продуктов.
- **Модуль 2. База рецептов** — `RecipeCatalog`, `Recipe`, `RecipeStep`:
  добавление рецепта с ингредиентами, граммовками, временем приготовления
  и текстовой инструкцией; просмотр рецептов.
- **Модуль 3. Smart Matcher** — `RecipeMatcherService`: сравнивает состав
  рецепта со складом, рецепт считается доступным, если хватает 100%
  ингредиентов; если чего-то не хватает — возвращается список недостающего.
- **Модуль 4. Покупки и хранилище** — `ShoppingList` (автогенерация списка
  покупок из недостающих ингредиентов выбранного рецепта) и `RecipeStorage`
  (сохранение и загрузка склада и базы рецептов в JSON-файл).

## Дальнейшие шаги (см. общий план проекта)

- Покрыть `RecipeMatcherService` unit-тестами.
- При желании обернуть в веб-интерфейс (ASP.NET Core/Blazor) — вся бизнес-
  логика в `Models/`, `Pantry/`, `Recipes/`, `Matcher/`, `Shopping/`,
  `Storage/` переиспользуется без изменений, поменяется только слой UI.
