# Bug Report — Smart Recipe Book

Найдено тестовым драйвером `SmartRecipeBook.Tests` (TestRunner) при прогоне
негативных сценариев по текущему коду модулей `Pantry` и `Matcher`.

| ID | Модуль и метод | Входные данные | Ожидаемый результат | Фактический результат |
|----|-----------------|------------------|------------------------|---------------------------|
| BUG-01 | `PantryManager.RemoveItem` | `RemoveItem("Молоко", -100)` при остатке 750 г | Списание отрицательного количества должно быть отклонено: метод возвращает `false`, остаток не меняется | Метод вернул `true`, остаток **увеличился** до 850 г (`Amount -= amount` при отрицательном `amount` превращается в сложение) |
| BUG-02 | `PantryManager.AddItem` | `AddItem("Мука", -50, Unit.Gram)` для продукта, которого ещё нет на складе | Отрицательное количество должно отклоняться — продукт не должен создаваться | Метод создал новый продукт `"Мука"` с отрицательным остатком `-50 г` (валидации входного `amount` нет) |
| BUG-03 | `RecipeMatcherService.Match` | Рецепт с ингредиентом `("Соль", -10, Unit.Gram)`, при этом на складе есть `"Соль"` в количестве `5 г` | Отрицательное (некорректное) требуемое количество — рецепт не должен считаться доступным по этому ингредиенту, либо должна быть ошибка валидации | Ингредиент не попал в `MissingIngredients`, `IsAvailable = true` — рецепт ошибочно считается доступным, потому что `availableAmount < required.Amount` не выполняется, если `required.Amount` отрицательный |

## Как воспроизвести

```bash
cd SmartRecipeBook.Tests
dotnet run
```

Ожидаемый вывод: **8 PASS, 3 FAIL** — упавшие тесты помечены как `(BUG-01)`,
`(BUG-02)`, `(BUG-03)` прямо в названии сценария.

## Рекомендация по исправлению (для протокола, не входит в текущую сдачу)

- **BUG-01**: в начале `PantryManager.RemoveItem` добавить `if (amount < 0) return false;`.
- **BUG-02**: в начале `PantryManager.AddItem` добавить `if (amount < 0) return;` (или бросать исключение / возвращать `bool`, аналогично `RemoveItem`).
- **BUG-03**: в `Recipe.AddIngredient` (или в начале `RecipeMatcherService.Match`) добавить проверку `if (amount < 0) throw new ArgumentException(...)`, чтобы некорректные данные не могли попасть в сравнение остатков.
